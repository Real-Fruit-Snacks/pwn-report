pwn-report

Private, evidence-linked reports from pwn-broker archives

pwn-broker keeps a box's targets, notes, credentials and files in order, and ends with one archive. pwn-report reads that archive and writes a report folder beside it: the box, its targets and flags, a timeline taken from the archive's own records, and an index of every scan, screenshot, exploit, loot file and recording, each with its SHA-256 and a link to its copy. It never runs anything from the archive, never contacts the network, and never changes the archive.

Report filed

What a report holds

The folder is made beside the archive and named after it, or wherever -o says. An existing folder is never replaced, so a report you have edited is safe. report.md has eight sections, in order: review status, box summary, targets, flags, timeline, evidence index, what is not in the index, and notes.

  • report.mdWhat to read
  • report.jsonAs data

    The same facts as data, with every source path and SHA-256.

  • report.tomlWhat built it

    Versions, the archive's SHA-256, and the selection's when one was given.

  • SHA256SUMSEvery file

    The SHA-256 of every other file in the folder.

  • evidence/The copies

    Copies of the scans, screenshots, exploits and notes it links, at their paths inside the box.

What it reads, and what it never does

  • Every listed fileAccounted for

    Scans, screenshots and exploits are indexed and copied. Loot, recordings and a target's files/ and upload/ are indexed and not copied unless a selection file includes them. Anything else is listed by its path under Not in the index.

  • Credential filesStay out

    It never reads creds.toml, lists/, targets/*/creds/ or tooldata/. notes.md and every copied file are as they were and can hold passwords; keep this report private. Each held-back place is named with its count of files, nothing more, and a selection file that names one is refused.

  • The archiveChecked, not trusted

    Every file the report uses has the size and SHA-256 the archive's manifest gives, or the build stops. Links, devices, paths that leave the box and archives past pwn-broker's own limits are refused before anything is read.

  • Running, the networkNever

    Archived files are read as bytes. There is no network code at all. The same archive gives the same report, byte for byte.

Choosing what goes in

A selection file adds captions and alt text and decides which indexed files are copied. Build with pwn-report build <archive> --select selection.toml. The guide has every field, and docs/selection.example.toml is a full one.

schema = 1

[[rule]]
path = "targets/dc01/loot/ntds.dit"
include = true
caption = "NTDS.dit copied off DC01 with the backup operator's rights"

Known issues

  • A private report by design: there is no public writeup mode, no redaction of notes or scans, and no secret scanning. Read what it reads before sharing one.
  • No findings, severities or narrative: the report states what the archive records.
  • On Windows, a path longer than 260 characters fails with the system's own message.
  • Files in the archive that its manifest does not list leave no trace in the report. pwn-broker lists every file except its own bookkeeping, and warns about any whose name is not UTF-8.
